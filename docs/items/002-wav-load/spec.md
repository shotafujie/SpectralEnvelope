# 仕様書: 音声ファイルの読み込み

- 関連ロードマップ項目: なし（001 の要件 §10 の拡張候補）
- 関連ADR: なし
- 作成日: 2026-09-18
- 前提: `001-envelope-jig` の仕様（特に SPEC-001〜014 の分解 API）

## 目的

録音の代わりに手元の音声ファイルを分解できるようにし、同じ音声で条件を変えた聴き比べを繰り返せるようにする。

## スコープ

### やらないこと

- サーバー API の変更（`/api/analyze` は wav 等を既に受け付ける。長さの扱いも SPEC-009/010 のまま）
- ページへのドラッグ＆ドロップでの読み込み
- 複数ファイルの一括読み込み

### やること

- UI にファイル選択を追加し、選んだファイルを録音と同じ流れで分解する

## 仕様

- **SPEC-300** UI に「ファイルを開く」ボタンがあり、ファイル選択の受け付け種別は `audio/*` と `.wav` である
- **SPEC-301** ファイルを選ぶと、そのファイルの内容がファイル名付きで `/api/analyze` の `audio` フィールドに送信される
- **SPEC-302** ファイルの分解が完了すると、録音の分解完了時と同じく、フレームスライダー・グラフ・元音/加工音ボタンが有効になり、以降の API 呼び出しは新しい `id` を使う
- **SPEC-303** ファイルの送信から応答までの間、「ファイルを開く」ボタンと録音ボタンは無効になる
- **SPEC-304** 録音中は「ファイルを開く」ボタンが無効である
- **SPEC-305** ファイルの分解がエラーになったとき、エラー表示領域にメッセージが出て、それ以前の分解結果があれば以降の API 呼び出しはその `id` を使い続ける
- **SPEC-306** 同じファイルを続けて 2 回選んでも、2 回とも `/api/analyze` に送信される

## 前提・依存

- ファイルの形式判定・変換はサーバー（ffmpeg）が行う。デコードできなければ SPEC-011 の 400 になる
