# テスト設計書: 音声ファイルの読み込み

- アイテムID: `002-wav-load`
- 仕様書: `docs/items/002-wav-load/spec.md`
- 作成日: 2026-09-18

## テスト方針

- すべて E2E（`tests/e2e/test_load.py`）。実サーバー + Playwright Chromium。ファイル選択は `set_input_files` で行う
- 観測点: `#open-file`（ボタン）、`#file`（`input[type=file]`）、および 001 の観測点
- 入力ファイル: 合成母音 wav（`tests/audio_fixtures.py`）を一時ディレクトリに書き出したもの

## テストケース

### SPEC-300 ファイルを開くボタンと受け付け種別

- **TC-300-1** ページ読み込み直後 → `#open-file` が表示され有効、`#file` の `accept` が `audio/*` と `.wav` を含む

### SPEC-301 ファイル名付きで送信

- **TC-301-1** `voice.wav` を選ぶ → `/api/analyze` の要求が 1 件、multipart 本文に `name="audio"` と `filename="voice.wav"` を含み、本文にファイルのバイト列を含む

### SPEC-302 分解完了後の状態

- **TC-302-1** ファイルを選んで分解完了 → フレームスライダーと元音/加工音ボタンが有効、`#graph` の `data-id` が応答の `id`、スライダー変更後の envelope 要求の `id` が応答の `id`
- **TC-302-2** 録音で分解した後にファイルを読み込む → 以降の envelope 要求と元音の src がファイル側の `id`

### SPEC-303 送信中は無効

- **TC-303-1** `/api/analyze` を保留してファイルを選ぶ → 保留中は `#open-file` と `#rec` が無効、要求を通して応答が返ると両方有効

### SPEC-304 録音中は無効

- **TC-304-1** 録音開始 → `#open-file` が無効、停止して分解完了 → 有効

### SPEC-305 エラー時は前の結果を使い続ける

- **TC-305-1** 録音で分解 → 0.5 秒の wav を選ぶ → エラー表示領域が空でなく、その後のスライダー変更による envelope 要求の `id` は録音の `id`
- **TC-305-2** 分解前にランダムバイトの `.wav` を選ぶ → エラー表示領域が空でなく、元音/加工音ボタンは無効のまま

### SPEC-306 同じファイルの再選択

- **TC-306-1** 同じファイルを 2 回続けて選ぶ → `/api/analyze` の要求が 2 件、2 つの応答の `id` が異なる
