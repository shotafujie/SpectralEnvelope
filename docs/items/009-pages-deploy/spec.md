# 仕様書: GitHub Pages への配信と CI

- アイテムID: `009-pages-deploy`
- 関連ロードマップ項目: なし（`docs/roadmap.md` は未作成）
- 関連ADR: `docs/adr/ADR-0002-wasm-artifact-delivery.md`（決定 2・4・5 と「影響」の各項）
- 作成日: 2026-09-22

## 目的

008 で「静的な配信だけで動く」状態になったアプリを、実際に GitHub Pages から配信する。

配信するのは誰でも取得できるバイナリなので、**配信されている `world.wasm` が、
リポジトリにあるソースから作られたものだと言える状態**を保つ（ADR-0002 の決定 4）。
そのために、CI で再ビルドしてバイト単位の一致を確かめ、通ったコミットだけを配信する。

## スコープ

### やること

- GitHub Actions のワークフロー（照合ジョブ・テストジョブ・デプロイジョブ）
- 配信物の組み立て（最小バンドル）
- WORLD のライセンス文の同梱と、画面からの参照
- glue（`world.mjs`）と `world.wasm` が新旧で混ざらないようにする（ADR-0002 の「影響」）
- Pages の配信元を GitHub Actions にする

### やらないこと

- **Pixel などの実機での性能計測**。不要と判断した（2026-09-22）
- **E2E（Playwright）を CI で回すこと**。手元で回す運用を続ける
- **独自ドメイン・PWA・オフライン対応・アクセス解析**
- **アプリの機能と見た目の変更** → 008 で確定している
- **`jig/`（v0.1.0）の配信**。凍結した参照実装なので配信しない

## 共通の定義

- **成果物** = `engine/world/world.mjs` と `engine/world/world.wasm` の 2 つ。ADR-0002 で決めた手順でビルドされ、リポジトリにコミットされている
- **スタンプ** = 成果物の SHA-256 を記録したファイル。`engine/world/build.sh` が成果物と一緒に書き出す
- **照合** = 固定したイメージで成果物を再ビルドし、コミット済みのものとバイト単位で比べること
- **配信物** = Pages へアップロードするファイル一式
- **配信 URL** = `https://shotafujie.github.io/SpectralEnvelope/`

## 仕様

### 照合

- **SPEC-1100** 照合は 1 つのスクリプトで実行でき、ワークフローと手元の両方が同じスクリプトを呼ぶ
- **SPEC-1101** 照合は `engine/world/build.sh` と同じイメージ（linux/arm64、ダイジェスト指定）で再ビルドする
- **SPEC-1102** 再ビルドした `world.wasm` と `world.mjs` が、コミット済みのものとバイト単位で一致するとき、照合は成功（終了コード 0）する
- **SPEC-1103** どちらか一方でも一致しないとき、照合は失敗（終了コード 0 以外）し、一致しなかったファイル名を出力する
- **SPEC-1104** スタンプに記録された SHA-256 が、コミット済みの成果物の SHA-256 と異なるとき、照合は失敗する

### ワークフロー

- **SPEC-1110** ワークフローは `push` と `pull_request` の両方で起動する
- **SPEC-1111** 照合ジョブは `ubuntu-24.04-arm` で動く
- **SPEC-1112** テストジョブは `npm run test:js` を実行し、1 件でも失敗すればジョブが失敗する
- **SPEC-1113** ワークフローが参照する外部の action は、すべて 40 桁のコミット SHA で固定されている
- **SPEC-1114** ワークフローは `pull_request_target` を使わない
- **SPEC-1115** ワークフロー全体の既定の権限は `contents: read` だけである

### 配信

- **SPEC-1120** デプロイジョブは `main` への push のときだけ実行される
- **SPEC-1121** デプロイジョブは、照合ジョブとテストジョブの両方が成功したときだけ実行される
- **SPEC-1122** `pages: write` と `id-token: write` は、デプロイジョブにだけ与えられる
- **SPEC-1123** 配信物の組み立ては 1 つのスクリプトで実行でき、ワークフローと手元の両方が同じスクリプトを呼ぶ
- **SPEC-1124** 配信物は、ルートの `index.html`、`app/` の 2 ファイル、`engine/` の JS と WASM（`build.sh` と `wrapper.cpp` は含まない）、WORLD のライセンス文だけからなる
- **SPEC-1125** 配信物の `app/` と `engine/` の各ファイルは、リポジトリの同じ位置のファイルとバイト単位で一致する
- **SPEC-1126** 配信物に `tests/`・`docs/`・`jig/`・`benchmarks/`・`third_party/world/src/`・`.git` は含まれない
- **SPEC-1127** ルートの `index.html` は `app/` へ送るだけの内容で、ブラウザで開くとアプリの画面になる
- **SPEC-1128** Pages の配信元は GitHub Actions である
- **SPEC-1129** 配信 URL が 200 を返し、その HTML から `app/` をたどるとアプリの画面が表示され、録音なしでもファイルの読み込みから再合成まで動く

### ライセンス

- **SPEC-1130** 配信物に WORLD のライセンス文（`third_party/world/LICENSE.txt` と同じ内容）が含まれる
- **SPEC-1131** アプリの画面に、WORLD を使っている旨とライセンス文への参照がある

### 成果物の対

- **SPEC-1140** `world.wasm` の取得 URL に、スタンプに記録された `world.wasm` の SHA-256 の先頭 12 桁が含まれる
- **SPEC-1141** glue（`world.mjs`）も同じスタンプの値を付けた URL で読み込まれる（新旧の組み合わせが起きない）
- **SPEC-1142** エンジンの読み込み後、スタンプの値が console に 1 回出力される
- **SPEC-1143** スタンプは `engine/world/build.sh` が成果物と同じディレクトリに書き出す

## 非機能要件

- **SPEC-1150** 照合ジョブとテストジョブを合わせた CI の実行時間が、10 分未満である

## 受け入れの目安

配信 URL を開いて、手元と同じように音を読み込み・加工・再生できること（人が確かめる）。

## v0.1.0 からの対応

このアイテムに対応する v0.1.0 の仕様は無い（配信の仕組みそのものが新規）。
