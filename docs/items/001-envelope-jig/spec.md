## 目的

その場で録音した自分の声を WORLD（pyworld）で分解し、スペクトル包絡（sp）だけを操作して再合成し、
元音と聴き比べることで「包絡をこう変えると声はこう変わる」を体で覚えるためのローカルツールを作る。

## スコープ

### やらないこと

- リアルタイム処理（録音 → 解析 → 再生のターン制）
- 複数人利用、認証、永続化（プロセス終了で保持データは消える）
- ファイルのアップロード UI（API は wav も受けるが、UI からは録音のみ）
- ap の加工、f0 の定数倍以外の加工
- 加工結果の書き出し、包絡のドラッグ編集、モーフィング、時間変化する加工
- 再生位置の同期（再生は毎回先頭から）

### やること

- ブラウザでの録音、pyworld による分解（f0 / sp / ap）、sp の加工、元の f0（×pitch）・ap での再合成
- 元音と加工音の A/B 比較再生、包絡カーブの重ね描き

## 共通の定義

- **F** = 1025（`fft_size` 2048 の CheapTrick のビン数）。ビン k の周波数は `freq[k] = k * 44100 / 2048`
- **log_sp** = `ln(sp + 1e-12)`。加工はすべてこの対数領域で行い、最後に `exp` で戻す
- **dB 表示値** = `10 * log10(sp + 1e-12)`（振幅基準 `20*log10(sqrt(sp))` と同値）
- **合成母音** = テスト用に生成する 44100Hz・3 秒の信号。f0 ≈120Hz の倍音の和で、各倍音の振幅を既知のフォルマント包絡で与えたもの
- **包絡差** = 2 つの sp について、双方で f0 > 0 のフレーム、かつ 50〜8000Hz のビンで取った dB 表示値の差の絶対値の平均

## 仕様

### 分解 API `POST /api/analyze`

- **SPEC-001** `/api/analyze` は multipart の `audio` フィールドで受けた webm/opus 音声を分解し、200 と JSON（`id`, `fs`, `duration`, `frames`, `fft_size`, `f0_mean`, `voiced_frames`）を返す
- **SPEC-002** `/api/analyze` は wav 音声（任意のサンプリング周波数・チャンネル数）も受け付け、44100Hz モノラルに変換してから分解する
- **SPEC-003** `/api/analyze` の応答の `fs` は 44100、`fft_size` は 2048 である
- **SPEC-004** 応答の `duration` は、変換後のサンプル数を 44100 で割った秒数である
- **SPEC-005** 応答の `frames` は、分解で得た f0 の要素数（= sp の行数）と一致する
- **SPEC-006** 応答の `voiced_frames` は、f0 > 0 のフレーム番号を昇順に並べたリストと一致する
- **SPEC-007** 応答の `f0_mean` は、f0 > 0 のフレームの f0 の算術平均である（有声フレームが無いときは 0）
- **SPEC-008** 応答の `id` は 8 文字の小文字 16 進文字列で、呼び出しごとに異なる値になる
- **SPEC-009** 変換後の音声が 1.0 秒未満のとき、`/api/analyze` は 400 と `detail` にエラーメッセージを含む JSON を返す
- **SPEC-010** 変換後の音声が 10.0 秒を超えるとき、`/api/analyze` は先頭 10.0 秒だけを分解し、`duration` は 10.0 になる
- **SPEC-011** 音声としてデコードできないデータを受けたとき、`/api/analyze` は 400 と `detail` にエラーメッセージを含む JSON を返す
- **SPEC-012** `audio` フィールドが無いとき、`/api/analyze` は 422 を返す
- **SPEC-013** 分解結果の保持は最大 10 件で、11 件目を分解すると最も古い `id` は以後のどの API でも 404 になる
- **SPEC-014** 分解済みの `id` について、11 件目が来るまでは各 API が 200 を返す（10 件目まで破棄されない）

### 元音 API `GET /api/original/{id}`

- **SPEC-020** `/api/original/{id}` は 200、`Content-Type: audio/wav`、16bit PCM・モノラル・44100Hz の WAV を返す
- **SPEC-021** `/api/original/{id}` が返す WAV のサンプル数は `duration × 44100` と一致する
- **SPEC-022** 保持していない `id` に対して `/api/original/{id}` は 404 を返す

### 合成 API `POST /api/synthesize`

- **SPEC-030** `/api/synthesize` は 200、`Content-Type: audio/wav`、16bit PCM・モノラル・44100Hz の WAV を返す
- **SPEC-031** `/api/synthesize` が返す WAV のサンプル数は元音のサンプル数と一致する
- **SPEC-032** `params` が省略または空オブジェクトのとき、返された音を再分解した sp と元の sp の包絡差が 1.0dB 以下になる（合成母音で測定）
- **SPEC-033** `params` 省略時、空オブジェクト時、全キーを初期値で指定した時の 3 つの出力はサンプル単位で同一である
- **SPEC-034** 合成結果の振幅が ±1 を超える部分は、16bit 化の際に ±32767 に飽和し、符号反転（ラップアラウンド）しない
- **SPEC-035** 保持していない `id` に対して `/api/synthesize` は 404 を返す
- **SPEC-036** `/api/synthesize` が再合成に使う ap は、分解時の ap と要素単位で同一である
- **SPEC-037** `/api/synthesize` が再合成に使う sp は、同じ `params` で `/api/envelope` が返す `modified_db` と全フレームで一致する（dB 換算で差 1e-6 以内）

### 包絡 API `POST /api/envelope`

- **SPEC-040** `/api/envelope` は `freq`, `original_db`, `modified_db` をそれぞれ 1025 要素の配列で返し、`freq[k] = k * 44100 / 2048` である
- **SPEC-041** `original_db` は指定フレームの元の sp の dB 表示値である
- **SPEC-042** `params` が省略または空オブジェクトのとき、`modified_db` は `original_db` と一致する（差 1e-6 以内）
- **SPEC-043** `frame` が 0 未満または `frames` 以上のとき、`/api/envelope` は 400 を返す
- **SPEC-044** 保持していない `id` に対して `/api/envelope` は 404 を返す
- **SPEC-045** 合成母音 /a/（F1 800Hz）と /i/（F1 300Hz）で、50〜8000Hz の `original_db` の最大値をとる周波数が互いに 200Hz 以上離れる

### パラメータの解釈

- **SPEC-050** `params` で未指定のキーは初期値（`formant` 1.0, `tilt` 0.0, `bands` [0,0,0,0], `smooth` 0, `pitch` 1.0）として扱われる
- **SPEC-051** `formant` は 0.60〜1.60 にクランプされる
- **SPEC-052** `tilt` は -12.0〜+12.0 にクランプされる
- **SPEC-053** `bands` の各要素は -12.0〜+12.0 にクランプされる
- **SPEC-054** `pitch` は 0.50〜2.00 にクランプされる
- **SPEC-055** `smooth` は整数に丸められ、0 以下は 0（無効）、1〜9 は 10、81 以上は 80 として扱われる
- **SPEC-056** `bands` の要素数が 4 でないとき、または数値でない値を含むとき、API は 422 を返す

### フォルマントシフト `formant`

- **SPEC-060** formant 比 r のとき、加工後 log_sp のビン k の値は、加工前 log_sp をビン位置 k / r で線形補間した値である
- **SPEC-061** k / r が F − 1 を超えるビンの値は、加工前 log_sp の最終ビンの値である
- **SPEC-062** 合成母音 /a/ に r = 1.25 を適用すると、50〜8000Hz の `modified_db` の最大値をとる周波数は `original_db` のそれの 1.25 倍 ±5% に移る
- **SPEC-063** 合成母音 /a/ を r = 1.25 で再合成した音を再分解すると、有声フレーム平均の包絡の最大値をとる周波数が元の 1.25 倍 ±5% に移る

### 平滑化 `smooth`

- **SPEC-070** smooth = N（N ≥ 10）のとき、各フレームの log_sp に正規直交 DCT-II をかけ、次数 N 以上の係数を 0 にして逆変換した結果が加工後 log_sp になる
- **SPEC-071** smooth = 0 のとき、平滑化は log_sp を変化させない

### スペクトル傾斜 `tilt`

- **SPEC-080** tilt = T のとき、各ビンの dB 表示値に `T * log2(max(freq, 20) / 1000)` dB が加算される

### バンドゲイン `bands`

- **SPEC-090** バンドゲイン [g0, g1, g2, g3] のとき、各ビンの dB 表示値に次のゲインカーブ G(f) が加算される
- **SPEC-091** G(f) は、f ≤ 500·2^(−1/3) で g0、500·2^(1/3) ≤ f ≤ 1500·2^(−1/3) で g1、1500·2^(1/3) ≤ f ≤ 4000·2^(−1/3) で g2、f ≥ 4000·2^(1/3) で g3 である
- **SPEC-092** 境界 fb ∈ {500, 1500, 4000} の前後 1/3 オクターブ（fb·2^(−1/3) < f < fb·2^(1/3)）では、下側ゲイン gL と上側ゲイン gH を `G = gL + (gH − gL) · (1 − cos(π · (log2(f/fb) + 1/3) / (2/3))) / 2` でつなぐ

### f0 スケール `pitch`

- **SPEC-100** 合成母音を pitch = 1.5 で再合成した音を再分解すると、双方で有声のフレームの f0 中央値が元の 1.5 倍 ±3% になる
- **SPEC-101** pitch を変えても、f0 = 0 のフレームは再合成に使う f0 でも 0 のままである
- **SPEC-102** pitch は `/api/envelope` の `modified_db` に影響しない

### 加工順序

- **SPEC-110** 加工は formant → smooth → tilt → bands の順で適用され、全パラメータ同時指定の結果はこの順で 1 つずつ適用した結果と一致する

### 非機能

測定条件: Apple Silicon Mac、ローカル実行、合成母音 3 秒、ウォームアップ 1 回後の 3 回の中央値。

- **SPEC-120** 3 秒の wav に対する `/api/analyze` の応答時間が 1.0 秒未満である
- **SPEC-121** 3 秒の音声に対する `/api/synthesize` の応答時間が 0.3 秒未満である
- **SPEC-122** サーバーの起動エントリポイント（`python jig/server.py`）は 127.0.0.1 のみで待ち受ける
- **SPEC-123** `GET /` は 200 と `text/html` の UI ページを返す

### UI: 録音

- **SPEC-200** 録音ボタンを押すと録音が始まり、録音中は経過秒数が表示されて増えていく
- **SPEC-201** 録音中に録音ボタンを押すと録音が止まり、録音データが自動で `/api/analyze` に送信される
- **SPEC-202** `/api/analyze` の送信から応答までの間、録音ボタンは無効になる
- **SPEC-203** 録音開始から 10 秒経つと、録音は自動で停止して `/api/analyze` に送信される
- **SPEC-204** 分解後に再度録音すると、以降の API 呼び出しは新しい `id` を使う
- **SPEC-205** 分解が一度も完了していない間、元音・加工音ボタンは無効である

### UI: 包絡グラフ

- **SPEC-210** 分解完了後、グラフに元包絡（グレーの線）と加工後包絡（グレー以外の色で、元包絡より太い線）が描かれる
- **SPEC-211** グラフの横軸は対数スケールで、左端が 50Hz、右端が 22050Hz である（周波数 f の x 位置は log(f/50)/log(22050/50) に比例）
- **SPEC-212** グラフの縦軸の上端は表示フレームの元包絡（50Hz 以上）の最大 dB + 5、下端はそこから 70dB 下である
- **SPEC-213** グラフには 500 / 1500 / 4000Hz の位置に縦線が描かれる

### UI: フレーム選択

- **SPEC-220** フレームスライダーの範囲は 0〜`frames`−1 である
- **SPEC-221** 分解完了直後のフレームスライダーの値は `voiced_frames` の中央の要素（添字 `len // 2`）である
- **SPEC-222** 無声フレーム（`voiced_frames` に無いフレーム）を選ぶと、無声である旨の表示が出て、有声フレームに戻すと消える
- **SPEC-223** フレームスライダーを変えると、デバウンス後に選んだフレームで `/api/envelope` が呼ばれる

### UI: パラメータ操作

- **SPEC-230** スライダーの 範囲・刻み・初期値 は formant 0.60〜1.60・0.01・1.00、tilt −12.0〜+12.0・0.1・0.0、bands 4 本 各 −12.0〜+12.0・0.1・0.0、smooth 0〜80・1・0、pitch 0.50〜2.00・0.01・1.00 である
- **SPEC-231** 各スライダーの隣の数値表示は、スライダーの現在値に追従する
- **SPEC-232** スライダーをダブルクリックすると、そのスライダーは初期値に戻る
- **SPEC-233** 「すべてリセット」ボタンを押すと、全パラメータスライダーが初期値に戻る
- **SPEC-234** パラメータを連続して変えている間は `/api/envelope` が呼ばれず、最後の変更から 300ms 後に 1 回だけ呼ばれる
- **SPEC-235** パラメータを変えても `/api/synthesize` は呼ばれない
- **SPEC-236** smooth スライダーで 1〜9 を選んだとき、グラフ更新・合成の要求では 10 として扱われる（SPEC-055 と同じ解釈がサーバーで行われる）

### UI: 再生・比較

- **SPEC-240** 加工音ボタンを押すと、その時点のスライダー値を `params` として `/api/synthesize` が呼ばれ、返った音が先頭から再生される
- **SPEC-241** `/api/synthesize` の応答待ちの間、加工音ボタンはローディング表示になる
- **SPEC-242** 元音ボタンを押すと、`/api/original/{id}` の音が先頭から再生される
- **SPEC-243** スペースキーを押すと、直前に再生したのが元音なら加工音を、加工音または未再生なら元音を先頭から再生する
- **SPEC-244** スライダーやボタンにフォーカスがあってもスペースキーは A/B 切り替えとしてだけ働き、ボタン押下・ページスクロールは起きない
- **SPEC-245** 新しく再生を始めると、再生中の音は停止する

### UI: プリセット

- **SPEC-250** プリセットボタンを押すとスライダーが次の値になり、記載の無いパラメータは初期値になる: 素通し（すべて初期値）、子供っぽく（formant 1.25, pitch 1.15）、太く（formant 0.85, tilt −3.0）、こもる（bands [+4, 0, −6, −10]）、のっぺり（smooth 16）

### UI: エラー表示

- **SPEC-260** API がエラー（4xx/5xx）を返したとき、画面のエラー表示領域にメッセージが表示される
- **SPEC-261** マイクを取得できなかったとき、画面のエラー表示領域にメッセージが表示される

## 受け入れ試聴（仕様外・人が判定）

テストで真偽を判定できないため仕様IDは振らない。結果は `verification.md` の「受け入れ試聴」節に記録する。
自動検査での代用指標は SPEC-032（M1）、SPEC-045（M2）、SPEC-062/063（M3）。

- M1: 実際の声で、元音と無加工再合成音の声質の差が聴き分けられない

- M3: formant スライダーを動かすと、グラフのピークが左右に動き、再生音の声質も同じ方向に変わる

## 前提・依存

- Python 3.13、pyworld 0.3.5（`setuptools<81` が必要: pyworld が `pkg_resources` を import するため）
- ffmpeg が PATH にあること（soundfile は webm/opus をデコードできないため、ffmpeg で wav に変換する）
- UI は Chromium 系ブラウザ（MediaRecorder の webm/opus 出力）を前提とする。E2E は Playwright の Chromium と偽マイク入力で行う
