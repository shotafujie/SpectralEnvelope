## テスト方針

| レベル | 対象 | 置き場所 | 実行コマンド |
|---|---|---|---|
| ユニット | パラメータの解釈、各加工、伸縮、dB 列、異常系 | `tests/js/engine-dsp.test.mjs` | `npm run test:js` |
| 統合 | Python 版との照合、再合成の経路（006 のエンジンを実際に呼ぶ） | `tests/js/engine-dsp-golden.test.mjs` | `npm run test:js` |
| 統合 | 照合用データの生成スクリプトの再現性とメタデータ | `tests/test_golden_dsp.py` | `.venv/bin/pytest tests/test_golden_dsp.py` |
| 性能 | 加工の速さ、基準値のファイル | `tests/js/engine-dsp-perf.test.mjs` | `npm run test:js` |

- **テストダブルは使わない。** 再合成は 006 の本物のエンジンを呼ぶ
- **期待値はテスト側で独立に計算する。** 実装の関数を呼んで期待値を作らない
  - 平滑化（SPEC-823）の期待値は、テスト側に置く定義どおりの DCT-II / IDCT-II（O(N²)、全 1025 次）で作る。実装側は必要な次数だけを計算するので、別の道筋で同じ値になることを確かめられる
  - 補間・ゲインカーブ・伸縮も、テスト側に独立した式を書く
- **入力**: 照合用データの 1 秒の分解結果（006 の `world-a-1s.*`）と、DSP の照合用データ（`dsp-*`）。3 秒・10 秒は性能テストだけで使う
- **許容差**: 仕様に書いてあるもの（1e-6 dB など）をそのまま使う。テスト側の独立計算と比べるケースは、丸めの差だけを許す 1e-9（dB 換算）とする
- **大きな配列の比較に `assert.deepEqual` を使わない。** 20 万要素の配列で食い違うと、Node が差分の整形に入って事実上戻ってこない。要素ごとの最大差を求めて 1 つの数値として判定する

### SPEC-821 `formant` 比 r の線形補間

- **TC-821-1** r = 1.25、フレーム 100 → 各ビン k の加工後 log_sp が、テスト側で `k / r` の線形補間として独立計算した値と 1e-9 以内で一致
- **TC-821-2** r = 0.8（縮小方向）→ 同様に一致

### SPEC-822 `k / r` が F − 1 を超えるビンは最終ビンの値

- **TC-822-1** r = 0.8（k / r が F − 1 を超えるビンが存在する）→ そのビンの加工後 log_sp が、加工前の最終ビンの値と一致

### SPEC-823 `smooth` = M の DCT-II による平滑化

- **TC-823-1** M = 30、フレーム 100 → テスト側の素朴な DCT-II / IDCT-II で次数 30 以上を 0 にした結果と 1e-9 以内で一致
- **TC-823-2** M = 80 → 同様に一致（次数が高いほど元に近い: M = 80 の結果は M = 30 の結果より元の log_sp に近い）

### SPEC-824 `smooth` = 0 は log_sp を変えない

- **TC-824-1** smooth 0 で log 形式の加工 → 入力の log_sp と全要素で同一

### SPEC-825 `tilt` のゲイン加算

- **TC-825-1** T = 6 → 各ビンの log_sp の差が `6 · log2(max(freq, 20) / 1000) · ln(10) / 10` と 1e-9 以内で一致
- **TC-825-2** T = −6 → 同様に一致

### SPEC-826 `bands` のゲインカーブ G(f)

- **TC-826-1** [6, 0, 0, 0] → 500·2^(−1/3) 以下のビンのゲインが 6dB 相当、1500·2^(1/3) 以上のビンが 0（log_sp の差で 1e-9 以内）
- **TC-826-2** [3, −3, 6, −6] → 全ビンの log_sp の差が、テスト側で独立計算した `G(freq) · ln(10) / 10` と 1e-9 以内で一致（クロスフェード区間を含む）

### SPEC-827 `curve` のゲインカーブ C(f)

- **TC-827-1** 20 要素の乱数（±12、固定の種）→ 全ビンの log_sp の差が、テスト側で独立計算した `C(freq) · ln(10) / 10` と 1e-9 以内で一致
- **TC-827-2** なだらかなカーブ（`c_j = −5 + 0.5·j`、隣り合う差 0.5dB）で、500Hz 以上の制御点 f_j について、もっとも近いビンでのゲインが c_j と ±0.05dB 以内（制御点の値が通ること）。ビンの位置は f_j と厳密には一致しないので、その分だけ許容する。500Hz 未満は、ビンの間隔（21.5Hz）が制御点の間隔に対して粗すぎるので対象にしない

### SPEC-828 `morph.ratio` = α の混合

- **TC-828-1** α = 0.4、相手は 1.5 秒の /i/ の log_sp → 全フレーム・全ビンで `(1 − α)·A + α·(伸縮後の B)` と 1e-9 以内で一致

## 観測点（仕様に無いものを覗かないための取り決め）

再合成の経路は、音と一緒に**その再合成に使った f0 / sp / ap** を返す形にする。
これは公開された戻り値であり、テストのための抜け道ではない（008 の Worker も、この値から描画用の dB 列を作る）。

→ 仕様書の SPEC-850 に、戻り値の形として追記する。
