# 仕様書: DSP の JS 移植（包絡の加工と再合成の経路）

- アイテムID: `007-engine-dsp`
- 関連ロードマップ項目: なし（`docs/roadmap.md` は未作成）
- 関連ADR: `docs/adr/ADR-0001-browser-world-engine.md`
- 作成日: 2026-09-21

## 目的

v0.1.0 が Python（NumPy / SciPy）で行っている包絡の加工を JS に移す。
加工の内容そのものは v0.1.0 の仕様（SPEC-050〜110、400〜411、500〜506）が正で、ここではそれを
「HTTP の API」ではなく「エンジンの関数」として言い直す。

移植が正しいことは、Python 版から作った照合用データとの一致で確かめる（ADR-0001 の決定 4）。

## スコープ

### やること

- パラメータの解釈（初期値、クランプ、丸め、形式の検査）
- 包絡の加工: morph → formant → smooth → tilt → bands → curve
- モーフ相手の伸縮
- 1 フレーム分の dB 列の出力（v0.1.0 の `/api/envelope` の中身に相当）
- 再合成の経路（加工した sp と `f0 × pitch` で 006 のエンジンを呼び、元音の長さに揃える）
- Python 版から作る照合用データの生成スクリプトと、そのデータ

### やらないこと

- **分解と再合成そのもの** → 006（このアイテムはそれを呼ぶ）
- **分解結果の保持、id の発行、Float32 での保持、LRU** → 008。このアイテムの関数は状態を持たず、引数で受けたものだけを使う
  - 保持のときに Float32 に落とす影響（ADR-0001 の決定 3）の照合も 008 で行う。このアイテムの照合はすべて Float64 のまま行う
- **Worker とのメッセージ、UI、音声のデコード** → 008
- **相手の録音を id で探すこと**（v0.1.0 の SPEC-408 が定める 404 の扱い）→ 008。このアイテムは相手の log_sp を引数で受け取る
- **新しい加工の追加や、既存の加工の挙動の変更**。移植であり、設計変更ではない

## 共通の定義

- **F** = 1025、**N** = フレーム数、**行優先の N×F 配列** = 006 と同じ
- **log_sp** = `ln(sp + 1e-12)`（001 と同じ）。dB のゲイン g を加えることは、log_sp に `g · ln(10) / 10` を加えることを指す（001 の「要件からの修正・補完」2 と同じ）
- **dB 値** = `10 · log10(sp + 1e-12)`（001 と同じ）
- **freq[k]** = `k · 44100 / 2048`
- **params** = `{ formant, smooth, tilt, bands, pitch, curve, morph }` の一部または全部を持つオブジェクト。`morph` は `{ ratio }`
- **解釈後の params** = 初期値の補完・クランプ・丸めを施した params（SPEC-800〜807）
- **伸縮後の B** = 003 と同じ。A のフレーム i に対し、B の位置 `p = i · (N_B − 1) / (N_A − 1)`（N_A = 1 のとき p = 0）で、B の log_sp をフレーム方向に線形補間したもの
- **制御点 f_j** = `50 · 400^(j/19)` Hz（004 と同じ）
- **ゲインカーブ C(f)** = 004 と同じ（制御点の値を log2(f) 上で線形補間、範囲外は端の値）
- **バンドゲイン G(f)** = 001 の SPEC-090〜092 と同じ
- **照合用データ（DSP）** = `tools/make_golden_dsp.py` が pyworld 0.3.5 と `jig/server.py` の関数を使って作り、`tests/golden/` にコミットしたファイル群
  - 入力は 006 と同じ合成母音 /a/ 1 秒（`world-a-1s.x.f64`）。モーフ相手は合成母音 /i/ 1.5 秒
  - パラメータの組は次の 7 つ: 初期値のみ / formant のみ / smooth のみ / tilt のみ / bands のみ / curve のみ / 全部（morph を含む）
  - 各組について、加工後の dB 列（フレーム 0・50・100・150・200 の 5 行）と、再合成した音 y（44100 サンプル）を記録する
  - 「全部」の組についてのみ、加工後の sp 全体（201×1025）も記録する

## 仕様

### パラメータの解釈

- **SPEC-800** 未指定のキーは初期値（`formant` 1.0、`tilt` 0.0、`bands` [0,0,0,0]、`smooth` 0、`pitch` 1.0、`curve` 20 要素すべて 0、`morph` なし）として解釈される
- **SPEC-801** `formant` は 0.60〜1.60 にクランプされる
- **SPEC-802** `tilt` は −12.0〜+12.0 にクランプされる
- **SPEC-803** `bands` の各要素は −12.0〜+12.0 にクランプされる
- **SPEC-804** `pitch` は 0.50〜2.00 にクランプされる
- **SPEC-805** `smooth` は整数に丸められ、0 以下は 0（無効）、1〜9 は 10、81 以上は 80 として解釈される
- **SPEC-806** `curve` の各要素は −12.0〜+12.0 にクランプされる
- **SPEC-807** `morph.ratio` は 0.0〜1.0 にクランプされる
- **SPEC-808** `bands` が配列でない、要素数が 4 でない、または数値でない値を含むとき、パラメータの解釈は TypeError を投げる
- **SPEC-809** `curve` が配列でない、要素数が 20 でない、または数値でない値を含むとき、パラメータの解釈は TypeError を投げる
- **SPEC-810** `formant`、`tilt`、`pitch`、`smooth`、`morph.ratio` に数値でない値を指定したとき、パラメータの解釈は TypeError を投げる

### 包絡の加工

- **SPEC-820** 包絡の加工は 2 つの形で提供される。**log 形式**は行優先の N×F の log_sp と params（必要なら伸縮後の B の log_sp）を受け取り、加工後の log_sp を同じ形で返す。**sp 形式**は sp を受け取り、`exp(log 形式(ln(sp + 1e-12)))` を返す
- **SPEC-819** 加工の本体は log 形式であり、sp 形式はその包みである。段を分けて逐次適用するときは log 形式を使う（sp 形式を繰り返すと、1e-12 を足す操作が段ごとに入り、平滑化がその差を全ビンに広げる）
- **SPEC-821** `formant` 比 r のとき、加工後 log_sp のビン k の値は、加工前 log_sp をビン位置 k / r で線形補間した値である
- **SPEC-822** k / r が F − 1 を超えるビンの値は、加工前 log_sp の最終ビンの値である
- **SPEC-823** `smooth` = M（M ≥ 10）のとき、各フレームの log_sp に正規直交 DCT-II をかけ、次数 M 以上の係数を 0 にして逆変換した結果が加工後 log_sp になる
- **SPEC-824** `smooth` = 0 のとき、平滑化は log_sp を変化させない
- **SPEC-825** `tilt` = T のとき、各ビンの log_sp に `T · log2(max(freq, 20) / 1000) · ln(10) / 10` が加算される（dB 値にすると `T · log2(max(freq, 20) / 1000)` dB の加算にあたる。sp が 1e-12 と同じ桁になるビンでは、dB 値の差はこれと厳密には一致しない）
- **SPEC-826** `bands` = [g0, g1, g2, g3] のとき、各ビンの log_sp に `G(freq) · ln(10) / 10` が加算される
- **SPEC-827** `curve` = [c_0, …, c_19] のとき、各ビンの log_sp に `C(freq) · ln(10) / 10` が加算される。C(f_j) は c_j と一致し、隣り合う制御点の間では log2(f) に対して線形である
- **SPEC-828** `morph.ratio` = α のとき、混合後の log_sp は、フレーム i ごとに `(1 − α) · (A の log_sp) + α · (伸縮後の B の log_sp)` である
- **SPEC-829** 加工は morph → formant → smooth → tilt → bands → curve の順に適用され、全パラメータを同時に指定した log 形式の結果は、log 形式で 1 つずつこの順に適用した結果と全要素で 1e-9 以内で一致する
- **SPEC-830** 解釈後の params がすべて初期値で `morph` が無いとき、log 形式の結果は入力の log_sp と全要素で同一である
- **SPEC-831** 包絡の加工は、引数の sp と相手の log_sp を書き換えない

### モーフ相手の伸縮

- **SPEC-835** 伸縮は、B の log_sp（N_B×F）と A のフレーム数 N_A を受け取り、N_A×F の log_sp を返す
- **SPEC-836** 伸縮後のフレーム i は、B の位置 `p = i · (N_B − 1) / (N_A − 1)` での線形補間と一致する（N_A = 1 のときは B のフレーム 0）
- **SPEC-837** N_A = N_B のとき、伸縮後の log_sp は B の log_sp と全要素で同一である
- **SPEC-838** `morph.ratio` が 1 で他のパラメータが初期値のとき、加工後の dB 列は伸縮後の B の dB 値と全要素で 1e-6 dB 以内で一致する

### 1 フレーム分の dB 列

- **SPEC-840** 包絡の出力は、フレーム番号と params を受け取り、`{ freq, originalDb, modifiedDb, partnerDb }` を返す。`freq`、`originalDb`、`modifiedDb` はそれぞれ長さ F の Float64Array
- **SPEC-841** `freq` の要素 k は `k · 44100 / 2048` である
- **SPEC-842** `originalDb` は、指定フレームの加工前の sp の dB 値である
- **SPEC-843** params が初期値のみのとき、`modifiedDb` は `originalDb` と全要素で 1e-6 dB 以内で一致する（`exp` と `ln` の往復の丸めだけが差になる。v0.1.0 の同じ趣旨の仕様と同じ許容差）
- **SPEC-844** 相手を指定したとき、`partnerDb` は指定フレームに対応する伸縮後の B の dB 値（長さ F の Float64Array）である
- **SPEC-845** 相手を指定しないとき、`partnerDb` は `null` である
- **SPEC-846** `pitch` は `modifiedDb` を変えない
- **SPEC-847** フレーム番号が 0 未満または N 以上のとき、包絡の出力は RangeError を投げる

### 再合成の経路

- **SPEC-850** 再合成の経路は、分解結果（f0 / sp / ap）、params、元音のサンプル数、必要なら相手の log_sp を受け取り、`{ y, f0, sp, ap }` を返す。`y` は長さが元音のサンプル数と同じ Float64Array で、`f0` / `sp` / `ap` はその再合成に渡した配列である（008 はこの `sp` から描画用の dB 列を作る）
- **SPEC-851** 再合成に使う fo は、分解時の f0 の各要素に `pitch` を掛けたものである
- **SPEC-852** f0 = 0 のフレームは、`pitch` を掛けても 0 のままである
- **SPEC-853** 再合成に使う ap は、分解時の ap と全要素で同一である（加工しない）
- **SPEC-854** 再合成に使う sp を `10 · log10(sp)`（1e-12 を足さない換算。`modifiedDb` と同じ）で dB にしたものは、同じ params で包絡の出力が返す `modifiedDb` と、全フレーム・全ビンで 1e-6 dB 以内で一致する
- **SPEC-855** 相手を指定しても、出力のサンプル数は元音のサンプル数と一致する

### Python 版との照合

- **SPEC-860** 照合用データの 7 つのパラメータの組それぞれについて、加工後の dB 列（5 フレーム分）が、照合用データと全要素で 1e-6 dB 以内で一致する
- **SPEC-861** 照合用データの 7 つのパラメータの組それぞれについて、再合成の経路の出力 y が、照合用データと全サンプルで絶対差 1e-6 以内で一致する
- **SPEC-862** 「全部」の組について、加工後の sp 全体（201×1025）の dB 値が、照合用データと全要素で 1e-6 dB 以内で一致する
- **SPEC-863** 照合用データの生成スクリプトを実行すると、コミット済みの照合用データとバイト単位で同一のファイルが出力される
- **SPEC-864** 照合用データには、生成に使った numpy、scipy、pyworld のバージョン文字列と、7 つのパラメータの組の中身が記録されている

### 異常系・境界

- **SPEC-870** sp の長さが N·F でないとき、包絡の加工は RangeError を投げる
- **SPEC-871** 相手の log_sp の長さが F の倍数でないとき、伸縮は RangeError を投げる
- **SPEC-872** `morph.ratio` が 0 のとき、加工後の log_sp は相手を指定しないときと全要素で同一である
- **SPEC-873** 相手として A 自身の log_sp を与えたとき（N_A = N_B）、`ratio` の値によらず加工後の dB 列は相手を指定しないときと 1e-6 dB 以内で一致する

## 非機能要件

測定条件: Apple M4 Max、Node 22、合成母音 /a/、初回を除く 5 回の中央値。

- **SPEC-880** 3 秒の分解結果（601 フレーム）に全パラメータを適用する時間が 0.3 秒未満である
- **SPEC-881** 10 秒の分解結果（2001 フレーム）に全パラメータを適用する時間が 1.0 秒未満である
- **SPEC-882** 1 フレーム分の dB 列の出力が 0.02 秒未満である（つまみ操作のたびに走るため）
- **SPEC-883** `benchmarks/engine-dsp/` に、上記 3 つの中央値の基準値と、計測に使ったコマンドがある

## 前提・依存

- 006 のエンジン（`engine/world-engine.mjs`）を使う。分析条件は 44100Hz / fft_size 2048 / frame_period 5ms で固定
- 照合用データの生成には Python 3.13、pyworld 0.3.5、`jig/server.py` の関数を使う
- JS 側のテストは Node 22 で動かし、照合用データを読むだけで Python も Docker も使わない
- 平滑化で使う DCT の係数は次数 80 未満だけなので（SPEC-805）、全 1025 次を求める必要はない。必要な次数だけを直接計算し、同じ係数で逆変換すれば、1 フレームあたり `2 · M · F` 回の積和で済む（M ≤ 80）。全 1025 次を素朴に計算すると SPEC-881 を満たせない
