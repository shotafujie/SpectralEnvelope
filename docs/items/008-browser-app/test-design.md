## テスト方針

| レベル | 対象 | 置き場所 | 実行コマンド |
|---|---|---|---|
| ユニット（Node） | 保持（id・LRU）、Float32 化の影響、情報の値の計算 | `tests/js/store.test.mjs` | `npm run test:js` |
| ブラウザ（統合） | アダプタ、Worker、デコード、静的配信、性能 | `tests/e2e/test_adapter.py` | `.venv/bin/pytest tests/e2e/test_adapter.py` |
| ブラウザ（E2E） | 画面の操作（v0.1.0 の E2E の移行先） | `tests/e2e/test_ui.py` ほか既存ファイル | `.venv/bin/pytest tests/e2e` |

### 観測点（v0.1.0 からの移行）

v0.1.0 の E2E は `/api/*` への要求を観測していた。ブラウザ版ではその要求が無くなるので、**アダプタを包んで観測する**。

- ページは読み込み時に `window.engine` を作る
- テストは `page.add_init_script` で、`window.engine` の 5 つの関数を包む記録係を仕込む。記録は `window.__calls`（`{ name, args, t }` の配列）に貯める
- 「要求が 1 回だけ出る」「要求が出ない」「要求の `params` が画面と一致する」は、この記録で判定する
- 「応答待ちの間の表示」は、テストから解決を保留できる形にする（`window.__hold = "synthesize"` を置くと、その呼び出しの解決をテストが指示するまで遅らせる）

この 2 つ（記録と保留）は、v0.1.0 の `page.expect_response` と `page.route` の代わりになる。

### 入力

- 偽マイク入力は v0.1.0 と同じ（Playwright の Chromium に wav を食わせる）
- ファイル読み込みのテストも v0.1.0 の `wav_files` フィクスチャを使う
- Node のテストは、006 / 007 の照合用データ（`tests/golden/`）を使う

### 許容差

- Float32 化の影響は仕様に書いた値（音は 1e-6、dB は 1e-3）
- 時間の判定は仕様の非機能要件の値

## テストケース

### SPEC-900 アダプタは 5 つの関数を持ち、すべて Promise を返す

- **TC-900-1** ページ読み込み後、`window.engine` の `analyze`・`envelope`・`synthesize`・`original`・`list` が関数で、`list()` の戻り値が `then` を持つ

- **TC-901-1** 3 秒の wav のバイト列と `"録音"` を渡す → `{ id, fs, fftSize, duration, frames, f0Mean, voicedFrames, source }` のキーがそろう

- **TC-902-1** 分解後に `envelope(id, 100, {})` → `freq`・`originalDb`・`modifiedDb` が長さ 1025 の配列で、`partnerDb` が `null`
- **TC-902-2** `tilt: 6` を指定 → `modifiedDb` − `originalDb` が全ビンで `6·log2(max(freq,20)/1000)` と 1e-6 dB 以内で一致

### SPEC-903 `synthesize(id, params)` の戻り値

- **TC-903-1** 分解後に `synthesize(id, {})` → Float32Array で、長さが元音のサンプル数と一致

### SPEC-904 `original(id)` の戻り値

- **TC-904-1** 分解後に `original(id)` → Float32Array で、長さが `duration × 44100` の整数部と一致
- **TC-904-2** /a/ と /i/ を分解 → 2 つの `original` が互いに異なり、/a/ の `original` が同じバイト列をデコードした波形と全サンプルで 1e-6 以内で一致する

### SPEC-905 `list()` の戻り値

- **TC-905-1** 3 件分解 → `list()` が 3 件を分解した順に返し、各要素が情報のキーを持つ
